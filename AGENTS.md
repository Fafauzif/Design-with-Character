# Working in Design With Character

For creative direction, visual revisions and new styles, read `skills/design-with-character/SKILL.md`. Use the actual audience and main action to choose the direction. Retain accepted parts of an existing product and describe the scope before changing public behavior.

For a multi-page project, identify what must repeat for orientation and what changes with each visitor task. Exercise deep entry, return, failure and recovery where applicable. Use actual content, rendered states and browser actions to support a design claim. A green build establishes technical checks; ask a fresh reader to try the experience where design judgment is involved.

Edit standalone examples in `styles/<slug>/`. Regenerate exports with `python scripts/build.py`. Read `CONTRIBUTING.md` before publishing a new style in the catalog. Keep additional art and third-party material traceable to its origin and terms. Preserve browser-local interactions and accessible alternatives to movement and sound.

For release changes, run the checks in README.md, including the representative Weather Cabinet plan and browser journeys. Scope work to the request. A copy change in one runtime should not force an unrelated redesign across every example.
