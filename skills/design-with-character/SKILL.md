# Design With Character

Begin with something a visitor actually came to do. Carry one idea far enough that a person can recognize the site on a deep link or after an action.

## Choose the job

| Request | Start here | Deliver |
|---|---|---|
| Diagnose a page or propose directions | Open the actual page or supplied image. Identify the visitor's first decision. Read [Direction](references/direction.md). | Specific findings or options in the requested scope. Honor a planning-only request. |
| Build or redesign | Inspect the existing entry points, assets, working behavior, and available tooling. Follow the build sequence below. | A functioning experience, including what happens after the opening view. |
| Develop a named style or expand the catalog | Read [Style families](references/styles.md) and [Author a style](references/author-style.md). | A working example, transfer guidance and a tested registration path appropriate to the user's project. |
| Review finished work | Render the real artifact. Read [Review](references/review.md). | Ranked, evidenced defects and verified fixes when authorized. Describe taste judgments as judgments. |

## Build sequence

1. **Lock the brief.** Identify the visitor, primary task, material to preserve, scope and delivery format. Treat approved motifs, functionality and constraints as input. Ask when the wrong choice would change the product, rights or audience. Resolve reversible details from evidence.
2. **Derive the idea.** Compare each reference's opening composition, first action and result. Name the obvious template this brief invites. Develop plausible alternatives by changing the action, space or content relationship. Select the one the material supports. Use [Direction](references/direction.md) when the choice is open or the current design feels generic.
3. **Map the experience.** For several routes, distinct audiences or repeat visits, use [Site architecture](references/site-architecture.md) before styling the entrance. For a small demo, sketch entry, action, result, and return. Preserve working state, ordinary navigation and text needed to complete the task. Pick the design language from [Style families](references/styles.md) if it fits. An original direction is a valid outcome.
4. **Build a representative journey first.** Include a real destination and a difficult state. Establish type, spacing, accent and controls against actual content. Apply the language across remaining route families. Read [Assets and motion](references/assets-motion.md) when introducing custom art, generated art, sound, or animated behavior.
5. **Enforce what can be observed.** Exercise critical journeys, inspect rendered views, and fix defects in severity order. Use [Review](references/review.md) for four distinct passes on a flagship or release; respect a user's requested review count. Keep internal critique and scores out of public UI. Deliver only claims supported by a check.

Use the project's native implementation and test commands. This skill also works with an empty project and a browser. When the Design With Character source kit is present, consult its README, CONTRIBUTING guide and CI for current commands. Its optional `scripts/project.py` offers `init`, `check`, `moves` and `record` for planning and project-local history. Use the family map and plain-text history in the guides when working without the kit.

For a complete example of an expressly digital site with no physical metaphor, read [The last eight counts](references/digital-example.md). Keep process notes temporary unless the user requests a handoff, the project already keeps design records, or the deliverable itself is a reusable system. Use [Sources and attribution](references/sources.md) when adapting external material.
