# Four reviews of a release

Run the complete first implementation before counting review rounds. Select realistic starting data and a task with a recognizable outcome. Each pass needs an artifact, an observation, a decision, and a recheck of the affected path. Repainting a screenshot or recording a higher score without a change provides no new evidence. Keep working records out of the shipped interface. For an up-to-four request, stop only when the agreed threshold is met; for four explicit passes, complete all four with distinct questions. A clean pass can stand on documented observations without a cosmetic edit.

| Pass | Give the evaluator | Inspect and act |
|---|---|---|
| 1. Character and reading | The first frames and states after a meaningful action, with realistic copy, across families. Give a fresh reader a task without narrating the design intent. | What is this place? Where would you start? Which two routes were hard to tell apart? Test an alternative arrangement or remove a competing signal. |
| 2. Complete trips | A live build and entry URLs, including a deep link. | Run the real visitor journey, return visit, keyboard path, back/forward, cancellation, clear or undo, and the chosen error state. Fix lost work or navigation before polish. |
| 3. Craft under stress | The build with changed viewport, content, input or motion preference. | Inspect the actual rendered result on small and wide screens, focus visibility and order, contrast, image crop, real media, zoom, long content, and reduced motion. Recheck the original view after fixing a narrow one. |
| 4. Handoff | A fresh extraction/checkout or equivalent clean deployment, without the author's open tabs or local cache. | Follow the public entry directions from scratch. If the output claims extensibility, add one temporary real example and open it. If the output is a site, deep-link to an interior page, then complete a task without prior briefing. |

Use a separate evaluator when available. Give them the artifact, audience and goal; omit intended diagnoses. A simulated first-time visitor is an independent agent review if another agent actually performed it. Distinguish it from a human audience study. If working alone, change the task, evidence or viewing condition each pass. Avoid inventing a disagreement to justify extra work.

## Evidence and release conditions

Implement machine checks for reproducible facts. Examples are stale build outputs, bad asset paths, duplicate route IDs, actual test failures, obstructed keyboard journeys, meaningful horizontal overflow, or unexpected motion in the reduced state. Require evidence for visual judgments: compare unlabelled compositions at the same size, inspect a crop around the actual control, or ask a fresh evaluator to choose a destination. A matching color, card count, or typography count alone cannot prove a template problem. Resolve or explicitly justify a repeated effect by family and user task.

For review scoring, rate task fulfillment, correctness, completeness, clarity/usability and presentation/execution independently on 0–10. A 5 requires major work, 7 is usable with clear deficits, 8.5 is strong with minor issues, and 9+ needs unusually strong evidence. A broken main action, missing requested outcome, or misleading data remains a blocker regardless of a mean. Record one observation and the main limitation per score. Mark unavailable evidence unverified. Use the agreed threshold for every applicable dimension, usually 8.5 for a release review; repair the highest-impact issue and retry the same check before raising any rating. Disclose material gaps if the limit on rounds is reached. Keep scores private unless requested.

Use actual text/background pairs, test visible focus and avoid relying on hue alone. For WCAG AA text contrast, the usual thresholds are 4.5:1 for ordinary text and 3:1 for large text; inspect the relevant non-text contrast requirements for component identification. Reflow tests commonly include 320 CSS pixels, allowing bounded two-dimensional content when necessary. Record the browser, actual viewport and interaction path checked. Browser emulation is evidence for that configuration; qualify claims about physical devices, screen readers or audio accordingly.
